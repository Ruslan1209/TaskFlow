# Обоснование связей TaskFlow

TaskList *-- Task (композиция): задача не существует без списка задач; удалили список — удалились и все его задачи, поэтому в коде это vector<Task> по значению.

Task o-- Tag (агрегация): тег живёт отдельно от задач и переиспользуется (один тег «учёба» у многих задач); удаление задачи тег не уничтожает, в коде это vector<Tag*>.

User --> TaskList (ассоциация): пользователь владеет ссылкой на свой список, но список создан отдельно и не умирает вместе с полем пользователя, в коде это указатель TaskList*.

Task --> Priority (зависимость): приоритет — это просто тип значения в поле задачи, у него нет своего поведения, поэтому отдельного класса-владельца здесь не нужно.

TaskList ..> TaskFilter (зависимость): фильтр передаётся только в параметре метода findBy, список его не хранит — поиск нужен временно, на один вызов.

TaskList ..> ITaskStorage (зависимость): список сохраняет и загружает задачи через хранилище, передаваемое извне; сам список не знает, где лежат данные.

Reminder ..> Task (зависимость): напоминание только проверяет даты задач, которые ему передали в методе check, и не владеет ими.

ITaskStorage <|.. FileStorage (реализация): FileStorage выполняет контракт интерфейса — умеет save и load, как требует ITaskStorage.

FileStorage <|-- CsvTaskStorage (наследование): CSV-хранилище — разновидность файлового; оно переиспользует имя файла из базового класса и добавляет только формат записи.
