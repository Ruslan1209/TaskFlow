# Обоснование решения ДЗ-3 (TaskFlow)

## Почему у задачи именно такие состояния

Новая — задача добавлена только в список, работа ещё не началась.
В работе — пользователь начал выполнять задачу.
Приостановлена — пользователь отложил работу; задача не потеряна, но и не двигается.
Просрочена — срок прошёл, задача не выполнена. Отдельное состояние нужно потому, что такая задача ведёт себя иначе: её нельзя приостановить, только восстановить или отправить в архив.
Выполнена — работа закончена, зафиксирована дата выполнения.
Отменена — пользователь решил задачу не делать.
В архиве — конечное хранилище: задача больше не показывается в активном списке.

«В работе» и «Приостановлена» объединены в составное состояние «Активна»: у них одинаковое поведение по отношению к отмене, завершению и истечению срока.

## Запрещённые переходы и почему

- Из «Новой» в «Выполнена» нельзя: нельзя решить задачу, не начав её. markDone() работает только из «В работе», «Приостановлена» и «Просрочена».
- Из «Новой» в «В архиве» нельзя: архив — место для завершённых и отменённых задач; сначала нужно отменить или выполнить задачу.
- Из «Выполнена» в «Отменена» нельзя: выполненную задачу нельзя отменить — результат уже есть; cancel() возвращает ложь.
- Из «Выполнена» в «В работе» нельзя: повторное выполнение не предусмотрено; чтобы переделать работу, создаётся новая задача.
- Из «В архиве» никуда нельзя: архив конечен; start(), pause(), markDone() из него не работают.

## Разрешённый неочевидный переход

«Просрочена» → «В работе» — метод start(today). Просроченную задачу можно переоткрыть и продолжить работу: срок прошёл, но сама задача ещё актуальна. Приостановить просроченную нельзя — pause() работает только из «В работе». Возврат в работу запрещён только для завершённых состояний: из «Выполненной» и «Архивной» задача не возвращается — там работа уже закончена, и start() не имеет смысла.

## Сторожевые условия

Условие [срок прошёл] стоит на переходе check(today): если сегодня позже даты задачи, статус станет «Просрочена».

Условие [дата не в прошлом] стоит на переходе start() из «Новой»: задачу с прошедшей датой начать нельзя — её можно только отменить.

## Диаграмма последовательности: сообщения и методы

- addTask(task) — TaskList::addTask(unique_ptr<Task>)
- setTitle(title) — Task::setTitle
- setDate(date) — Task::setDate
- setPriority(priority) — Task::setPriority
- setStatus(NEW) — Task::setStatus
- save(list, path) — ITaskStorage::save, реализовано в TxtTaskStorage::save
- ответ true — возвращаемое значение addTask() и save()
